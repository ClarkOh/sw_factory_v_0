# tools

## `vm_gui.py` — 자판기 조작 화면

v7 산출물을 손으로 시험하는 화면. `python tools/vm_gui.py` 로 띄우고
`http://127.0.0.1:8765` 를 연다.

**실제 제품을 그대로 구동한다.** `app.vending_machine.VendingMachine` 을 import 해서
`handle(event, **payload)` 를 부를 뿐이고, 화면은 이벤트를 보내고 관측값을 받아 그린다.
판단은 전부 제품이 한다.

브라우저에서 돌리려고 JS 로 다시 짜지 않은 이유: v7 의 guard·action 이 115개 함수 3,132줄이다.
다시 짜면 원본과 갈라지고, 그러면 화면을 조작해도 *그 제품* 을 시험한 게 아니게 된다.

### 화면 구성

| 면 | 내용 |
|---|---|
| 왼쪽 | 자판기 — 표시창(상태·누적액), 음료 슬롯(가격·재고·활성 램프), 코인 투입, 반환 레버, 배출 완료 신호, 배출구·반환구·동전통 |
| 가운데 | 그 외 이벤트 — 전원 / 시간 경과 / 관리자 / 보충·회수. payload 는 명세 표에서 자동 생성 |
| 오른쪽 | FSM 전이 기록 — `이전 상태 → 이후 상태 (T-xxx)`. 전이가 없으면 그 사실을 표시 |

### 알아 둘 것

- 이벤트 목록과 payload 필드는 제품이 만든 `app/_fsm_spec.py` 에서 읽는다. 하드코딩이 아니다.
- **초기화는 채워진 저장 파일을 먼저 만든다.** 제품은 `POWER_ON` 때 저장 파일에서 장부를
  복원하므로(요구사항 30), 파일이 없으면 재고 0 으로 기동하고 관리자를 부른다 — 그게 정상 동작이다.
  그 '처음 설치' 경로를 보려면 `POST /api/reset {"stocked": false}`.
- 비활성 버튼도 눌러 볼 수 있다. 눌러서 아무 일도 안 일어나는 것을 확인하는 것도 시험이다.

### 다른 버전 시험

    python tools/vm_gui.py --repo baselines/2026-09-01_vending_machine_v6/repo --port 8766

v6 은 이벤트 이름이 다르다(`RETURN_LEVER` vs `PULL_RETURN_LEVER` 등). 화면은 명세 표를 읽으므로
그대로 뜬다.

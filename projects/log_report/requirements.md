# Claude Code 사용량 집계기

Claude Code 가 남기는 세션 기록을 주기적으로 읽어 자체 저장소에 적재하고,
그것을 근거로 기간별 사용량 리포트를 만든다. 운영자가 "지금 세션 칸을 얼마나 썼나",
"이번 주 얼마나 썼나"를 답할 수 있게 하는 것이 목적이다.

같은 일을 하는 수제 구현(tools/usage_server.py)이 이미 돌고 있고, 그것이 이 도구의
**대조 기준**이다. 수제 구현에서 실제로 겪은 결함 — 중복을 안 걸러 1.8배 부풀었던 것,
실측과 3배 어긋난 원인을 추적할 수 없었던 것, 저장소가 무한정 자라는 것 — 이
아래 요구사항의 출처다.

## 원천

1. 원천은 `~/.claude/projects/**/*.jsonl` 파일들이다. 한 줄이 JSON 레코드 하나다.
2. **원천은 읽기 전용이다.** 어떤 경우에도 원천 파일을 수정하거나 지우지 않는다.
   원천은 다른 프로그램(Claude Code)의 소유물이다.
3. 수집은 증분이다. 파일마다 지난번 읽은 위치를 기억하고 새로 붙은 부분만 읽는다.
   파일이 줄어들었으면(회전) 처음부터 다시 읽는다.
4. 수집은 주기적으로 반복 실행된다. 같은 원천 상태에서 몇 번을 돌려도
   저장소는 같은 상태여야 한다 — 재실행이 레코드를 복제하면 안 된다.

## 레코드 채택

5. 사용량 레코드는 `type` 이 `assistant` 이고 `message.usage` 에 토큰 수가 있는 것이다.
   그 외의 줄(사용자 발화, 첨부, 시스템)은 조용히 지나가는 것이 아니라 **무관 레코드로 센다.**
6. 한 API 요청이 여러 레코드로 나뉘어 기록되고 각각이 같은 usage 를 단다.
   `requestId` 가 같은 레코드는 하나만 채택하고 나머지는 **중복으로 센다.**
   (수제 구현은 이걸 늦게 발견해 사용량이 1.8배로 부풀어 있었다.)
7. JSON 으로 파싱되지 않는 줄, usage 는 있으나 토큰 수가 전부 0이거나 없는 레코드는
   **무효로 세고 이유를 남긴다.**
8. 채택한 레코드에서 뽑는 값: 시각(UTC), 모델 이름, 세션 id, 입력·출력·캐시읽기·
   캐시쓰기(5분/1시간 구분) 토큰, 웹검색 횟수.
9. 비용은 모델별 단가표로 계산한다. 단가표에 없는 모델은 **가장 비싼 단가로 계산하고
   그 사실을 리포트에 표시한다** — 비용을 낮게 보여주는 쪽으로 틀리면 안 된다.

## 저장과 보존 기한

10. 채택한 레코드는 자체 저장소에 적재한다. 저장소는 원천과 별개 파일이다.
11. **저장소는 무한정 자라면 안 된다.** 두 층으로 보존한다:
    - 원시 레코드: **8일** (주간 리포트 창 7일 + 여유 1일)
    - 일 단위 요약(날짜·모델별 토큰·비용·채택/중복/무효 건수): **35일**
12. 보존 기한을 넘긴 원시 레코드는 삭제하되, **삭제 전에 그 날의 일 요약에 반영되어
    있어야 한다.** 요약에 없는 레코드를 지우면 그 사용량은 영영 사라진다.
13. 삭제는 조용히 하지 않는다. 언제 몇 건을 지웠는지 적재 장부에 남는다.
14. 수집 1회의 결과는 장부 한 줄로 남는다: 읽은 줄 수, 채택, 중복, 무효, 무관,
    보존 삭제 건수. **읽은 줄 수 = 채택 + 중복 + 무효 + 무관** 이 항상 성립한다.
14-1. **적재 장부 자신도 자라면 안 된다.** 장부 줄은 35일 보존한다. 그보다 오래된
    줄은 지우되, 지우기 전에 그 날의 일 요약에 건수(채택·중복·무효·무관·보존 삭제)가
    반영되어 있어야 한다 — 원시 레코드와 같은 규칙이다.
14-2. **이 도구가 쓰는 모든 파일(저장소·일 요약·적재 장부·읽기 위치 상태)은 기간
    또는 크기 상한을 갖는다.** 상한 없이 자라는 쓰기는 그 자체로 결함이다.
    일 요약과 읽기 위치 상태는 항목 수가 날짜·파일 수에 비례하므로 자연히 유계지만,
    사라진 원천 파일의 읽기 위치는 함께 정리한다.

## 리포트

15. 리포트 기간은 셋이다: 세션 칸(5시간), 하루(24시간), 주간(7일).
16. 기간이 원시 레코드 보존 범위 안이면 원시 레코드로, 벗어나면 일 요약으로 집계한다.
    일 요약으로도 답할 수 없는 기간은 **값 없음으로 표시한다.** 0으로 적으면
    "안 썼다"로 읽힌다.
17. 리포트에는 모델별 분해(토큰 종류별, 비용)와 일별 추이(최근 30일)가 들어간다.
18. 리포트에는 근거가 붙는다: 어느 저장소 상태(마지막 적재 시각, 레코드 수)에서
    나왔는지. 같은 저장소 상태에서 두 번 만들면 같은 리포트가 나온다.
19. 리포트의 총 토큰은 저장소의 해당 기간 레코드 합과 같아야 한다.
    칸별 합계가 총계와 다른 리포트는 만들지 않는다.

## 실패

20. 원천 파일 하나를 읽지 못해도 나머지로 진행한다. 어느 파일이 왜 실패했는지
    장부에 남긴다.
21. 저장소 파일이 깨져 있으면 원천에서 다시 지을 수 있어야 한다. 단, 원시 보존
    기한(8일)을 넘긴 과거는 복구할 수 없다는 사실을 명시적으로 알린다.
22. 원천 디렉터리가 없으면 빈 저장소로 시작한다. 오류가 아니다.

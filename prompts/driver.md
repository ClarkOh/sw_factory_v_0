아래 FSM 구현을 **실행 가능한 프로그램**으로 만드는 진입점을 작성하세요.

구현은 이미 존재하며 순수 도메인 로직입니다. 당신이 만들 것은 그 위에 얹는 얇은 껍데기입니다.

## 만들 파일: `app/__main__.py`

`python -m app` 으로 실행되어야 합니다.

## 요구사항

1. **도메인 코드를 수정하지 마세요.** `app/__main__.py` 하나만 만듭니다.
   기존 클래스를 import 해서 씁니다. 생성자에 필요한 초기값(재고, 가격 등)은
   이 파일 안에 데모용 기본값으로 둡니다.

2. **두 가지 모드**를 지원합니다:
   - 인자 없이 실행 → 대화형 REPL. 사용 가능한 이벤트를 안내하고,
     한 줄씩 입력받아 처리하고, 매번 현재 상태를 보여줍니다. `quit` 으로 종료.
   - `--script <파일>` → 파일에서 한 줄에 한 이벤트씩 읽어 비대화형으로 실행.
     자동화·검증용입니다. 마지막에 최종 상태를 출력합니다.

3. **입력 형식**은 `EVENT key=value key=value` 로 합니다.
   예: `INSERT_COIN amount=500 recognized=true`
   값은 `true`/`false` → bool, 숫자 → int, 나머지는 문자열로 변환합니다.

4. **매 이벤트마다** `이전상태 --EVENT--> 이후상태` 를 출력합니다.

5. **아무 일도 일어나지 않았을 때, 그 이유를 정확히 구분해서 말해야 합니다.**
   이게 이 프로그램에서 가장 중요한 부분입니다. 두 상황은 정반대 의미인데
   "전이 없음" 한마디로 뭉뚱그리면 진단이 쓸모없어집니다:

   - **명세에도 없는 조합** → 사용자가 잘못된 이벤트를 보냈다
   - **명세에는 있는데 구현이 아직 없다** → 공장이 아직 안 지었다 (진행 중)

   구분은 직접 하지 마세요. 공장이 `app/_fsm_spec.py` 를 이미 생성해 두었습니다:

   ```python
   from app._fsm_spec import diagnose, expected, EVENTS, TRANSITIONS

   before = vm.state
   vm.handle(event, **payload)
   moved = vm.state != before          # 또는 관측 가능한 부수효과가 생겼는지
   note = diagnose(before, event, moved)
   if note:
       print("   ", note)
   ```

   `_fsm_spec.py` 는 fsm.yaml 에서 기계적으로 생성된 것이라 항상 정확합니다.
   **전이 표를 직접 베껴 쓰지 말고 반드시 import 해서 쓰세요.**

6. **아직 구현되지 않은 전이**가 있을 수 있습니다. 크래시 없이 계속 진행해야 합니다.

7. 시작할 때 **구현 진행률**을 한 줄 보여주세요. `TRANSITIONS` 중 실제로 동작하는 것이
   몇 개인지는 알 수 없으므로, 명세된 전이 총 개수와 "일부는 미구현일 수 있음"만 알리면 됩니다.

8. 표준 라이브러리만 씁니다. 외부 의존성 추가 금지.

9. 잘못된 입력(모르는 이벤트, 깨진 key=value)에 크래시하지 말고 안내 메시지를 출력하세요.
